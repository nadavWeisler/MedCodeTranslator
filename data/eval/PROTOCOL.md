# Held-out IR evaluation protocol

This is the published retrieval evaluation for MedCodeTranslator. It is **not**
the hand-written fixture gate in `data/benchmarks/`.

## Task

Known-item lexical lookup: given a query derived from a vocabulary row, retrieve
that row's code (and any other row with the identical official English name).

This is not a clinician-judged relevance study. Graded judgments and user studies
are out of scope.

## Held-out set

`heldout-queries.json` is generated by `node scripts/heldout_ir_eval.js --generate`.

1. Load the pinned vocabularies listed in `data/vocabularies/source-metadata.json`.
2. Drop ICD-11 (bundled 64-row demo subset).
3. Exclude any row whose official name or code appears in:
   - `data/benchmarks/*.json` (fixture regression / marketing-adjacent queries)
   - `app/constants/searchExamples.ts` (UI demo chips)
4. Drop generic labels (`unspecified`, `other specified`, `combinations`, `NOS`, …)
   and labels shared by more than five codes.
5. Deterministically shuffle remaining rows with Mulberry32, seed `20260906`.
6. Take a fixed quota per scheme and assign query types in round-robin:
   - `official_label` — full `name_en`
   - `label_typo` — one deleted interior character
   - `exact_code` — the stored code string

Queries are not written to pass the product demos. Regenerating with the same
seed and the same pinned vocabs must reproduce the committed file.

## Metrics

Computed in `scripts/lib/ir_metrics.js` against a cutoff of 10:

| Metric | Definition |
|---|---|
| **MRR** | Mean reciprocal rank of the first relevant code |
| **nDCG@k** | Binary-gain nDCG |
| **P@k** | True precision: \|relevant ∩ top-k\| / k |
| **Success@k** | 1 if any relevant code is in the top k (the fixture gate's "P@k") |

Do not call Success@k "precision".

## Systems

| System | Implementation | License / extras |
|---|---|---|
| **layered** | In-repo exact → prefix → substring → Fuse.js → alias (`scripts/lib/layered_search.js`) | None |
| **fts5** | SQLite FTS5 `ORDER BY rank` on `code`, `name_en`, `name_he` (`scripts/fts5_baseline.py`) | Python stdlib sqlite3 |

Athena and UTS/UMLS are not used: Athena is a hosted service and UTS requires an
NLM license. FTS5 runs against the same pinned JSON files in CI.

## How to run

```bash
# Regenerate the held-out set after a vocabulary pin change
npm run eval:heldout:generate

# Score layered vs FTS5 and refresh data/eval/heldout-report.json
npm run eval:heldout
```

A full score run is a few minutes (ICD-10 has 74k rows). `--generate` only writes the query file.

Published numbers must come from `data/eval/heldout-report.json` (macro and
per-scheme tables written by the harness). Do not quote fixture `expected_codes`
P@k as an information-retrieval result.
